# План: адаптивная раскладка и HUD для Hand Duel

> Задача для агента-исполнителя. Сначала прочитай `AGENTS.md` (стек, команды, системы координат).
> Решение по UX согласовано с владельцем проекта, менять концепцию не нужно. Детали реализации — на твоё усмотрение в рамках описанного.

## 0. Контекст: что сейчас не так

Текущая раскладка (`src/effects.ts`, метод `layout()`) жёстко делит экран пополам по горизонтали: соперник сверху (`foeRect`), ты снизу (`meRect`). Каждое видео cover-кропается в свою половину. HUD — DOM поверх canvas (`index.html`: `#hp-me`, `#hp-foe`, `#status`, `#spell`, `#ko`).

Проблемы, найденные на реальном скриншоте (окно браузера ~1024×600):

1. **Сильный кроп.** Половина 1024×300 (3.4:1) против камеры 16:9 → теряется ~50% кадра по высоте. У соперника видно только нос и рот.
2. **Видимая область ≠ область трекинга.** MediaPipe видит весь кадр камеры, а на экране показан кроп. Рука может «работать» за краем видимой части, тогда щит и портал рисуются за экраном. **Это главная проблема UX.**
3. **HUD нечитаемый:** две тонкие полоски HP без подписей и чисел, непонятно, где чья. Статус мелкий, внизу слева.
4. **Противоречивые состояния:** одновременно «ПОБЕДА» по центру и «Соперник отключился — жду…» внизу. Надпись KO лежит на стыке половин. Реванша нет, после KO только перезагрузка.
5. **В бою нет подсказок по жестам и кулдаунам**, непонятно, почему каст не сработал.

## 1. Цель

- Видео каждого игрока показывается **целиком или почти целиком** (кроп ≤ ~10%), с пропорциями **его собственной камеры** (у соперника может быть телефон вертикально, 3:4 или 9:16).
- Раскладка **выбирается автоматически** по размеру и ориентации окна и пересчитывается на `resize` и `orientationchange`.
- HUD живёт в **выделенных зонах** (свободное место вокруг панелей), а не поверх лица.
- Нормально играется на маленьком разрешении (телефон вертикально, ноутбук 1366×768, окно ~800×500).

## 2. Алгоритм раскладки

Новый модуль `src/layout.ts`, чистые функции без DOM и three.js, чтобы их было легко проверить.

### 2.1 Входные данные

```ts
interface LayoutInput {
  vw: number; vh: number;      // CSS-размер окна (innerWidth/innerHeight, лучше visualViewport)
  meAspect: number;            // videoWidth / videoHeight своей камеры
  foeAspect: number;           // аспект камеры соперника (до прихода стрима = meAspect)
  safe: { top: number; right: number; bottom: number; left: number }; // env(safe-area-inset-*)
}
type Orientation = "stack" | "side";   // stack: соперник сверху, ты снизу; side: соперник слева, ты справа (или наоборот, см. 2.4)
interface Rect { x: number; y: number; w: number; h: number } // screen px, y вниз
interface LayoutResult {
  orientation: Orientation;
  foe: Rect; me: Rect;          // прямоугольники видео-панелей
  arena: Rect;                  // полоса между панелями (для сообщений и центра траекторий)
  hudFoe: Rect; hudMe: Rect;    // зоны HUD каждого игрока
  compact: boolean;             // мало места → компактный HUD (см. 4.4)
}
```

### 2.2 Расчёт

1. Вычесть safe-area и минимальные зоны HUD:
   - `stack`: сверху табличка соперника, снизу панель спеллов, между панелями полоса арены (≈ `clamp(24px, 4vh, 48px)`).
   - `side`: боковые колонки HUD шириной `clamp(120px, 16vw, 220px)` и полоса арены между панелями.
2. Для каждой ориентации посчитать размер панелей при **contain-fit** с учётом аспекта каждой камеры. Обе панели **одинаковой высоты** в `side` и **одинаковой ширины** в `stack` («два равных окна» — пожелание владельца).
3. Разрешить небольшой дополнительный **cover-кроп до `MAX_CROP = 0.1`** (10% по одной оси), если он заметно увеличивает площадь (убирает тонкие чёрные поля).
4. Выбрать ориентацию с **максимальной суммарной площадью видео**. Гистерезис: переключаться, только если выигрыш > 8%, иначе раскладка будет дёргаться при ресайзе.
5. Центрировать группу (панели + арена) в доступной области. Остаток пространства — зоны HUD.

Ожидаемое поведение (проверь вручную или юнит-проверкой функции):

| Окно | Камеры | Ожидаемо |
|---|---|---|
| 1024×600 | 16:9 / 16:9 | `side` или `stack` с полями по бокам; лица видны целиком |
| 1920×1080 | 16:9 / 16:9 | `side` |
| 390×844 (телефон верт.) | 3:4 / 16:9 | `stack` |
| 844×390 (телефон гориз.) | 4:3 / 4:3 | `side`, `compact = true` |
| 800×500 | 16:9 / 16:9 | работает, `compact = true` |

### 2.3 Связь с трекингом (критично)

- Свой кроп сейчас хранится в `Effects.meCrop` и используется в `camToScreen()`. После изменений `camToScreen` должен по-прежнему точно повторять **ту же** трансформацию, что применяется к текстуре (`setCrop` в `layout()`): учитывать текущий `me` rect, кроп и зеркалирование.
- Так как кроп теперь ≤ 10%, рука почти никогда не уходит за видимую область. Если всё же уходит (точка за пределами `me` rect), подсвечивать край панели (см. 4.5).
- Щит, портал и старт своих снарядов должны оставаться в своей панели (clamp к `me` rect с небольшим допуском).

### 2.4 Ориентация `side`: кто слева

Соперник **слева**, ты **справа**: свои спеллы под правой рукой привычнее. Значение вынести в константу.

## 3. Изменения в `Effects` (`src/effects.ts`)

- `layout()` больше не считает прямоугольники сам: вызывает `computeLayout()` из `layout.ts` и применяет результат (позиции и масштаб мешей `me` и `foe`, кропы текстур, юниформы портала `u_myCrop` / `u_oppCrop`, вспышка `flash`).
- Аспект соперника брать из `foeTex.image.videoWidth/videoHeight` и пересчитывать раскладку на `loadedmetadata` и `resize` удалённого видео (у телефона аспект меняется при повороте).
- Хранить последний `LayoutResult` и отдавать наружу (`get layoutResult()`), чтобы `main.ts` расставил DOM-HUD по тем же прямоугольникам.
- **Траектории снарядов строить по прямоугольникам панелей**, а не по долям `this.h`:
  - `spawnOutgoing`: от точки руки внутри `me` к краю `me`, обращённому к сопернику (в `stack` верхний край, в `side` левый), с уменьшением, будто снаряд улетает вглубь.
  - `spawnIncoming(spell, nx)`: старт у края `foe`, обращённого к тебе, позиция вдоль края = `nx`. Цель — точка в `me` (сейчас `h * 0.88` → теперь ~85% глубины `me` rect по оси полёта), разброс ±6% размера панели.
  - В `side` полёт горизонтальный, `nx` тогда задаёт вертикальную позицию. Логику оформить одной функцией с осью `axis = orientation === "stack" ? "y" : "x"`.
- `onRemoteBlocked` в `game.ts` сейчас рисует бёрст в фиксированной точке `(w/2, h*0.86)`, хотя должен рисовать у края своей панели, обращённого к сопернику, в точке, откуда ушёл снаряд. Добавить в `Effects` метод `outgoingExitPoint(nx)`.
- `shieldRadius` масштабировать от размера `me` rect (например `0.14 * min(me.w, me.h)`), а не держать 120 px: на телефоне щит сейчас огромный, на 4K маленький. Аналогично `spell.radius` при рендере и коллизиях домножать на общий масштаб `scale = min(me.w, me.h) / 540`.
- Рендер учитывает `devicePixelRatio` (уже ≤ 2); на `compact` снижать до 1.5 ради FPS на слабых телефонах.

## 4. HUD (DOM, `index.html` + `src/hud.ts`)

Всё, что связано с HUD, вынести из `main.ts` в новый модуль `src/hud.ts` с классом `Hud`. Он реализует интерфейс `GameUi` из `game.ts` (интерфейс расширить) и метод `applyLayout(LayoutResult)`, который позиционирует блоки абсолютными координатами из прямоугольников. Размеры шрифтов и отступов через `clamp()`.

### 4.1 Таблички игроков (`.plate`)

- Над панелью соперника (в `stack`) или в его колонке (в `side`): **«СОПЕРНИК»**, полоса HP, число `72/100`. Цвет красно-розовый (как сейчас `#hp-foe`).
- У своей панели: **«ТЫ»**, полоса HP, число. Цвет зелёный.
- При уроне: короткая встряска таблички и всплывающее `−10` (CSS-анимация). При хиле `+8` зелёным.
- Табличка привязана к краю панели, не к краю экрана.

### 4.2 Панель спеллов (`.spellbar`)

- У своей панели (снизу в `stack`, в правой колонке в `side`). Иконки всех заклинаний из `SPELLS` плюс щит ✋ и портал 🤲.
- Каждая иконка: эмодзи жеста, название (скрывается в `compact`), **круговой индикатор кулдауна** (`conic-gradient` по CSS-переменной `--cd: 0..1`).
- **Подсветка текущего распознанного жеста** — главное средство против «почему не скастовалось»:
  - жест распознан, но на кулдауне → иконка подсвечена серым, кольцо видно;
  - жест распознан и готов → яркая подсветка в момент каста.
- Для этого `GestureInterpreter` (`src/spells.ts`) должен отдавать оставшийся кулдаун (`cooldownLeft(spellId, now): number` в долях 0..1), а `Game.onHands` передавать в HUD текущий жест (`ui.gesture(spellId | "shield" | "portal" | null)`). Обновлять кулдауны в rAF-цикле, не по событию трекера.
- Таблица жестов в лобби (`#hint`) остаётся, но строится из `SPELLS`, без дублирования строкой в HTML.

### 4.3 Полоса арены (`.arena`)

- Узкая полоса между панелями: декоративная линия-«барьер» (CSS-градиент).
- Сюда идут короткие сообщения-тосты: «Заблокировано!», «Лёд: попадание −6», «Соперник подключился». Максимум 2 одновременно, живут ~1.5 с.
- `#status` в углу убрать. Технические статусы (загрузка модели, ошибки камеры) показывать в **оверлее загрузки** (4.6), а не в бою.

### 4.4 Компактный режим (`compact`)

Включается, если высота окна < 500px **или** ширина < 420px **или** панели получаются меньше 260px по короткой стороне:
- в спелбаре только иконки, без подписей; иконки ≥ 36px;
- шрифты не меньше 12px;
- табличка в одну строку: метка + полоса + число;
- тосты — одна строка, меньший шрифт.

### 4.5 Индикатор выхода из кадра

Если сглаженная ладонь (до кропа) находится в пределах ~6% от края кадра камеры или за видимой частью, соответствующий край своей панели светится (CSS `box-shadow inset` на DOM-рамке поверх панели либо полоса в three.js). Подсказка в тосте: «Руку в кадр». Не чаще раза в 3 с.

### 4.6 Состояния экрана (машина состояний)

Сейчас состояния размазаны по `setStatus`. Ввести явный `type Phase = "lobby" | "loading" | "waiting" | "fight" | "over"` в `main.ts`. Каждый оверлей показывается только в своей фазе; это исправляет баг «ПОБЕДА + Соперник отключился».

- **`lobby`** — текущий `#join`. Таблица жестов из `SPELLS`.
- **`loading`** — оверлей поверх своей панели: «Камера…» → «Модель…» со спиннером. Ошибки камеры (`CAMERA_ERRORS` в `tracker.ts`) показываются здесь, с кнопкой «Повторить».
- **`waiting`** — своя панель уже живая, в **панели соперника**:
  - код комнаты крупно;
  - кнопка **«Скопировать ссылку»** (`navigator.clipboard.writeText(location.href)`, тост «Скопировано»);
  - **QR-код** ссылки, чтобы зайти с телефона. Зависимость не нужна: либо минимальный QR-энкодер на ~150 строк в `src/qr.ts`, либо, если это слишком дорого, пропустить QR и оставить только ссылку (решение исполнителя, отметить в отчёте);
  - пока ждём, тренировка: свои касты работают визуально, по сети не уходят.
- **`fight`** — по `onPeerJoin` + приходу стрима. Короткий отсчёт «3-2-1-БОЙ» в арене, во время отсчёта касты игнорируются.
- **`over`** — модалка по центру **всего экрана**, не на стыке: «ПОБЕДА» / «ПОРАЖЕНИЕ», итоговый HP, кнопки **«Реванш»** и **«Выйти»**.
  - Реванш — новый экшен в `net.ts`: `rematch` (запрос) и подтверждение. Когда оба нажали, `Game.reset()` (HP 100/100, очистить снаряды, кулдауны, `over = false`) и снова отсчёт. Пока ждём второго игрока: «Ждём соперника…».
  - «Выйти» — `session.leave()`, остановить трекер и треки камеры, вернуться в `lobby` (или просто `location.href = location.pathname`).
- **Соперник отключился** (`onPeerLeave`): в `fight` → пауза-оверлей в его панели «Соперник отключился — ждём переподключения», через 20 с предложить «Выйти». В `over` → только тост, модалку не трогать.

## 5. Мобильные мелочи

- Кнопка **полноэкранного режима** (⛶) в углу HUD: `document.documentElement.requestFullscreen()`; на iOS Safari API нет — кнопку скрывать, если `!document.fullscreenEnabled`.
- **Wake Lock** (`navigator.wakeLock?.request("screen")`) на время `fight`, переподключать на `visibilitychange`.
- Высота: использовать `100dvh` и `visualViewport` для расчётов, иначе панель адресной строки мобильного браузера ломает раскладку.
- `viewport-fit=cover` в meta viewport и учёт `env(safe-area-inset-*)` (вырез экрана).
- На телефоне в горизонтальной ориентации с очень малой высотой (< 360px) показывать подсказку «Поверни телефон вертикально» (не блокирующую).

## 6. Что НЕ менять

- Трекинг, воркер, модель, сетевой транспорт (trystero), формат существующих экшенов `cast/block/hp/ko`. Новые экшены только добавлять.
- Баланс спеллов в `SPELLS`.
- Логику L-рамки `isFrameHand` и шейдер портала (только юниформы кропа, если меняется их смысл).
- Папку `public/`.

## 7. Порядок работы

1. `src/layout.ts` — `computeLayout()`. Проверить таблицу из 2.2: временный скрипт через `node` или `console.table` в dev, потом удалить.

3. `src/hud.ts` + разметка и стили в `index.html`: таблички, спелбар, арена, `applyLayout`.

5. Машина фаз в `main.ts`, оверлеи loading/waiting/over, ссылка (+ QR по возможности).
